# 抖音分享视频下载器

`tk_downloader` 是一个最小、可审查的 Go 命令行工具。它接收抖音 App 复制出的完整分享文案或作品链接，从官方移动分享页解析作品信息，并把页面提供的视频流保存为本地 MP4。

程序不依赖第三方解析网站，不需要登录，也没有内置浏览器或 JavaScript 签名实现。当前目标是稳定完成单个公开视频的下载闭环，而不是覆盖批量下载、直播、图集等所有抖音内容形态。

## 使用前提

- Go 1.23 或更高版本。
- 当前网络可以访问抖音分享页和视频 CDN。
- 作品是无需登录即可打开的公开视频。
- 仅下载自己拥有或已获授权保存的内容，并遵守平台条款及所在地法律。

## 快速开始

在仓库根目录执行：

```bash
go run ./utils/video/tk_downloader \
  -o ./downloads \
  'video share url'
```

也可以只传作品链接：

```bash
go run ./utils/video/tk_downloader \
  -o ./downloads \
  'link'
```

`-o` 用来指定保存目录，省略时保存到当前目录：

```bash
go run ./utils/video/tk_downloader 'link'
```

下载成功后会输出作品元数据和实际文件路径：

```text
下载完成
作者: 周期
作品: 丘比特的力气太小 只穿透了我一个人的心 #年下#湿发#土象#氛围感
文件: downloads/周期_丘比特的力气太小 只穿透了我一个人的心 #年下#湿发#土象#氛围感_7664176772422146725.mp4
```

如果同名文件已经存在，程序不会覆盖原文件，而是生成：

```text
周期_丘比特的力气太小_7664176772422146725 (1).mp4
```

## 构建独立可执行文件

```bash
go build -o ./bin/tk-downloader ./utils/video/tk_downloader
```

之后可以直接运行：

```bash
./bin/tk-downloader -o ./downloads '粘贴完整抖音分享文案'
```

查看参数：

```bash
./bin/tk-downloader -h
```

按 `Ctrl+C` 可以取消正在进行的页面请求或视频下载。取消或网络失败时，临时文件会被清理，不会留下看似完整但实际损坏的 MP4。

## 支持范围

当前支持：

- 带有 `v.douyin.com` 短链接的完整分享文案。
- `douyin.com/video/{作品ID}` 形式的作品链接。
- 无需登录即可访问的单个视频作品。
- 自动解析作者、标题、作品 ID 和播放地址。
- 流式下载、文件名清理和同名文件保护。

当前不支持：

- 私密、好友可见或必须登录的作品。
- 图集、直播、合集和批量账号下载。
- 验证码自动处理及登录 Cookie 注入。
- 保证无水印。程序保存官方分享页 `play_addr` 当前提供的版本。
- 下载进度、断点续传和多清晰度选择。

这些边界是刻意保留的：第一版只依赖公开分享页的服务端渲染数据，避免把易失效的内部签名接口或第三方服务引入核心链路。

## 实现原理

### 1. 从分享文案提取链接

抖音复制的内容通常同时包含标题、话题、口令和 URL。`share.go` 先扫描文本中的 HTTP URL，再只接受 HTTPS 的 `douyin.com` 或 `iesdouyin.com` 域名及其子域名。

域名判断要求主机名等于允许域名，或者以 `.` 加允许域名结尾。因此：

```text
v.douyin.com                 允许
www.iesdouyin.com            允许
douyin.com.evil.example      拒绝
```

这既允许用户直接粘贴分享文案，也避免程序被用来请求任意地址。

### 2. 请求移动端分享页

短链接会重定向到类似下面的页面：

```text
https://www.iesdouyin.com/share/video/{作品ID}/...
```

桌面端访问作品页时，抖音可能只返回需要执行 JavaScript 的风控启动页。移动端分享页则会把作品数据服务端渲染到 HTML 中。因此 `resolver.go` 使用固定的移动端 User-Agent，并跟随受限制的抖音域名跳转。

分享页响应最多读取 4 MiB。这个限制足以容纳当前 SSR 页面，同时防止错误响应或异常上游无限消耗内存。

### 3. 解析 `_ROUTER_DATA`

移动分享页包含类似结构：

```html
<script>
window._ROUTER_DATA = {
  "loaderData": {
    "video_(id)/page": {
      "videoInfoRes": {
        "item_list": [ ... ]
      }
    }
  }
}
</script>
```

解析器只用字节搜索定位 `window._ROUTER_DATA` 的赋值边界，内部嵌套数据始终交给 Go 的 `encoding/json` 解码，不用正则表达式解析 JSON。

程序遍历 `loaderData`，而不是写死 `video_(id)/page` 这个路由键。找到包含 `videoInfoRes.item_list` 的节点后，只提取四个必要字段：

```go
type VideoInfo struct {
    ID       string
    Author   string
    Title    string
    MediaURL string
}
```

这样上游 JSON 增加统计、推荐、评论等字段时，不会影响下载逻辑；如果未来分享页结构发生变化，也只需要修改解析层。

### 4. 获取并下载媒体流

视频入口来自：

```text
video.play_addr.url_list[0]
```

该地址通常不是最终文件，而是先经过抖音媒体网关，再重定向到视频 CDN。下载请求携带与分享页一致的移动端 User-Agent 和分享页 Referer，并且每次重定向都会重新校验目标域名。

媒体响应必须是成功状态，并且不能是 HTML、JSON 等明显的错误页面。视频正文通过固定大小缓冲区直接写入磁盘，因此内存使用量不会随视频大小增长。

### 5. 临时文件与原子发布

下载时先在目标目录创建隐藏的 `.part` 临时文件：

```text
.周期_标题_作品ID.mp4-123456.part
```

只有媒体流完整写入并成功关闭后，程序才通过同目录硬链接发布最终文件。这个策略有两个目的：

1. 下载中断时，用户不会看到一个扩展名为 `.mp4` 的损坏文件。
2. 发布操作不会覆盖已经存在的同名视频，避免检查文件后再重命名产生竞争窗口。

发布完成后临时文件会被删除；任何错误路径也会尽力清理临时文件。

## 代码结构

```text
utils/video/tk_downloader/
├── main.go             命令行参数和主流程
├── share.go            分享文本解析与域名边界
├── http_client.go      受限制的 HTTP 跳转策略
├── resolver.go         分享页请求和作品数据解析
├── downloader.go       媒体流下载和文件发布
├── *_test.go           单元及本地 HTTP 集成测试
└── README.md           使用和实现说明
```

数据流保持单向：

```text
分享文本
  -> extractShareURL
  -> resolver.Resolve
  -> VideoInfo
  -> downloader.Download
  -> 本地 MP4
```

解析层不写文件，下载层不理解抖音页面 JSON，CLI 只负责组合两者。这样的边界足够支撑当前需求，也为以后增加清晰度选择或其他作品解析方式保留了明确变化点。

## 测试

运行该目录的测试：

```bash
go test ./utils/video/tk_downloader
```

测试不依赖真实抖音网络，覆盖：

- 完整分享文案和长链接提取。
- 仿冒域名拒绝。
- `_ROUTER_DATA` 到 `VideoInfo` 的映射。
- 短链跳转和移动端请求头。
- 媒体重定向与流式保存。
- 同名文件不覆盖。
- HTML 风控响应不被误存为 MP4。

真实链接仍然应该在发布前人工运行一次，因为抖音页面和 CDN 策略属于程序控制范围之外的外部依赖。

## 常见错误

### `没有找到受支持的抖音 HTTPS 分享链接`

输入中没有抖音链接，链接被截断，或者传入了非抖音域名。重新从抖音复制分享文案并用引号包住整个文本。

### `抖音返回了风控校验页，请稍后重试`

当前 IP 或访问频率触发了页面校验。程序不会绕过验证码。稍后重试，或先确认同一链接能否在普通浏览器无登录打开。

### `作品播放地址不在受信任的媒体域名下`

抖音改变了媒体域名或页面返回了异常数据。应先人工确认新域名确实属于抖音媒体链路，再更新 `mediaHostSuffixes`，不要直接取消域名校验。

### `媒体服务器返回了非视频内容`

播放地址返回了网页或接口错误，而不是视频流。常见原因是链接过期、作品权限变化或媒体网关风控。

### 文件发布失败

确认输出目录可写，并且目标目录与临时文件位于支持硬链接的同一文件系统。程序总是在目标目录内部创建临时文件，因此普通本地磁盘满足该条件。
