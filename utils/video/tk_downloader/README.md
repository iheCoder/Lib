# 分享视频下载器

`tk_downloader` 是一个最小、可审查的 Go 视频下载工具，同时提供网页端和命令行。它接收 App 复制出的完整分享文案或作品链接，从官方移动分享页解析作品信息，保存为本地 MP4。

程序不依赖第三方解析网站，不需要登录，也没有内置浏览器或 JavaScript 签名实现。当前目标是稳定完成单个公开视频的下载闭环，而不是覆盖批量下载、直播、图集等所有内容形态。

## 使用前提

- Go 1.23 或更高版本。
- 当前网络可以访问分享页和视频 CDN。
- 作品是无需登录即可打开的公开视频。
- 仅下载自己拥有或已获授权保存的内容，并遵守平台条款及所在地法律。

## 网页端使用

在仓库根目录启动本地网页服务：

```bash
go run ./utils/video/tk_downloader -web
```

终端出现下面的提示后，在浏览器打开对应地址：

```text
网页端已启动: http://127.0.0.1:17846
按 Ctrl+C 停止服务
```

网页中的操作流程：

1. 粘贴完整分享文本或作品短链接。
2. 点击“解析视频”。
3. 确认作者、标题和文件名。
4. 点击“下载原片”，浏览器将直接保存 MP4。

需要修改监听地址时使用：

```bash
go run ./utils/video/tk_downloader -web -addr 127.0.0.1:18080
```

服务默认只监听本机回环地址，不对局域网或公网开放。解析结果在内存中保存十分钟，下载时由服务端把媒体源直接流式传给浏览器，不会先在项目目录生成视频副本。

## 命令行使用

在仓库根目录执行：

```bash
go run ./utils/video/tk_downloader \
  -o ./utils/video/tk_downloader/downloads \
  'video share url'
```

也可以只传作品链接：

```bash
go run ./utils/video/tk_downloader \
  -o ./utils/video/tk_downloader/downloads \
  'link'
```

`-o` 用来指定保存目录，省略时保存到当前目录：

```bash
go run ./utils/video/tk_downloader 'link'
```

下载成功后会输出作品元数据和实际文件路径：

```text
下载完成
作者: zhou
作品: 作品 X
文件: 文件 X.mp4
```

如果同名文件已经存在，程序不会覆盖原文件，而是生成：

```text
文件 X (1).mp4
```

## 构建独立可执行文件

```bash
go build -o ./bin/tk-downloader ./utils/video/tk_downloader
```

之后可以直接运行：

```bash
./bin/tk-downloader -o ./downloads '粘贴完整分享文案'
```

查看参数：

```bash
./bin/tk-downloader -h
```

按 `Ctrl+C` 可以取消正在进行的页面请求或视频下载。取消或网络失败时，临时文件会被清理，不会留下看似完整但实际损坏的 MP4。

## 支持范围

当前支持：

- 带有 `v.douyin.com` 短链接的完整分享文案。
- `douyin.com/video/{作品ID}` 形式的作品链接。
- 无需登录即可访问的单个视频作品。
- 自动解析作者、标题、作品 ID 和播放地址。
- 下载无平台水印、无引流尾帧的原始作品内容流。
- 流式下载、文件名清理和同名文件保护。

当前不支持：

- 私密、好友可见或必须登录的作品。
- 图集、直播、合集和批量账号下载。
- 验证码自动处理及登录 Cookie 注入。
- 上传母版下载。公开分享链路可能只开放转码后的最高可用版本，而不开放创作者上传时的母版文件。
- 下载进度、断点续传和多清晰度选择。

这些边界是刻意保留的：第一版只依赖公开分享页的服务端渲染数据，避免把易失效的内部签名接口或第三方服务引入核心链路。

## 实现原理

### 1. 从分享文案提取链接

复制的内容通常同时包含标题、话题、口令和 URL。`share.go` 先扫描文本中的 HTTP URL，再只接受 HTTPS 的 `douyin.com` 或 `iesdouyin.com` 域名及其子域名。

域名判断要求主机名等于允许域名，或者以 `.` 加允许域名结尾。因此：

```text
v.douyin.com                 允许
www.iesdouyin.com            允许
douyin.com.evil.example      拒绝
```

这既允许用户直接粘贴分享文案，也避免程序被用来请求任意地址。

### 2. 请求移动端分享页

短链接会重定向到类似下面的页面：

```text
https://www.iesdouyin.com/share/video/{作品ID}/...
```

桌面端访问作品页时，可能只返回需要执行 JavaScript 的风控启动页。移动端分享页则会把作品数据服务端渲染到 HTML 中。因此 `resolver.go` 使用固定的移动端 User-Agent，并跟随受限制的域名跳转。

分享页响应最多读取 4 MiB。这个限制足以容纳当前 SSR 页面，同时防止错误响应或异常上游无限消耗内存。

### 3. 解析 `_ROUTER_DATA`

移动分享页包含类似结构：

```html
<script>
window._ROUTER_DATA = {
  "loaderData": {
    "video_(id)/page": {
      "videoInfoRes": {
        "item_list": [ ... ]
      }
    }
  }
}
</script>
```

解析器只用字节搜索定位 `window._ROUTER_DATA` 的赋值边界，内部嵌套数据始终交给 Go 的 `encoding/json` 解码，不用正则表达式解析 JSON。

程序遍历 `loaderData`，而不是写死 `video_(id)/page` 这个路由键。找到包含 `videoInfoRes.item_list` 的节点后，只提取四个必要字段：

```go
type VideoInfo struct {
    ID       string
    Author   string
    Title    string
    MediaURL string
}
```

这样上游 JSON 增加统计、推荐、评论等字段时，不会影响下载逻辑；如果未来分享页结构发生变化，也只需要修改解析层。

### 4. 获取原始作品内容流

分享页的视频入口来自：

```text
video.play_addr.url_list[0]
```

这个字段当前给出的是 `/aweme/v1/playwm/` 分享流。它会把平台水印烧录进画面，并可能在原作品之后附加搜索引流尾帧，因此不能直接作为原始作品下载。

解析器保留同一个 `video_id`，将媒体网关切换为 `/aweme/v1/play/`，删除仅服务于水印展示的 `logo_name` 参数，并请求 `2160p`。该参数表达期望的最高规格，实际文件由服务端按作品可用档位向下协商：

```text
/aweme/v1/playwm/?ratio=720p&logo_name=...&video_id=xxx
                         ↓
/aweme/v1/play/?ratio=2160p&video_id=xxx
```

对 README 示例作品的实测结果是：

| 入口 | 分辨率 | 时长 | 内容 |
|------|--------|------|------|
| `/playwm/` | 720×1280 | 7.964 秒 | 带号水印，并包含引流尾帧 |
| `/play/` | 1080×1920 | 4.933 秒 | 无平台水印，无引流尾帧 |

作品元数据声明的画布尺寸是 2160×3840，但对 `/play/` 请求 `2160p`、`2k` 或 `4k` 时，服务端均返回同一个 1080×1920 文件。这说明公开分享链路没有开放该作品的上传母版。程序保证下载公开链路中的最高验证原内容流，不会把 1080p 转码文件虚称为逐字节一致的上传母版。

媒体网关随后会重定向到视频 CDN。下载请求携带与分享页一致的移动端 User-Agent 和分享页 Referer，并且每次重定向都会重新校验目标域名。

媒体响应必须是成功状态，并且不能是 HTML、JSON 等明显的错误页面。视频正文通过固定大小缓冲区直接写入磁盘，因此内存使用量不会随视频大小增长。

### 5. 临时文件与原子发布

下载时先在目标目录创建隐藏的 `.part` 临时文件：

```text
.文件 X.mp4-123456.part
```

只有媒体流完整写入并成功关闭后，程序才通过同目录硬链接发布最终文件。这个策略有两个目的：

1. 下载中断时，用户不会看到一个扩展名为 `.mp4` 的损坏文件。
2. 发布操作不会覆盖已经存在的同名视频，避免检查文件后再重命名产生竞争窗口。

发布完成后临时文件会被删除；任何错误路径也会尽力清理临时文件。

## 代码结构

```text
utils/video/tk_downloader/
├── main.go             命令行参数和主流程
├── share.go            分享文本解析与域名边界
├── http_client.go      受限制的 HTTP 跳转策略
├── resolver.go         分享页请求和作品数据解析
├── downloader.go       媒体流下载和文件发布
├── tickets.go          网页下载票据及过期管理
├── web_server.go       嵌入式静态服务和 Web API
├── web/                HTML、CSS、交互脚本和视觉资产
├── *_test.go           单元及本地 HTTP 集成测试
└── README.md           使用和实现说明
```

数据流保持单向：

```text
分享文本
  -> extractShareURL
  -> resolver.Resolve
  -> VideoInfo
  -> downloader.Download
  -> 本地 MP4
```

解析层不写文件，下载层不理解页面 JSON，CLI 只负责组合两者。这样的边界足够支撑当前需求，也为以后增加清晰度选择或其他作品解析方式保留了明确变化点。

网页端在相同核心链路上增加两个边界：

```text
POST /api/resolve
  -> 解析分享文本
  -> 创建随机下载票据
  -> 返回作品信息和本地下载地址

GET /api/download/{ticket}
  -> 校验十分钟有效期
  -> 打开受信任的媒体源
  -> 流式传输到浏览器
```

浏览器不会收到上游媒体网关地址。解析 API 只接受同源 JSON 请求，页面使用严格的内容安全策略，不加载第三方脚本、字体或统计服务。

## 测试

运行该目录的测试：

```bash
go test ./utils/video/tk_downloader
```

测试不依赖真实网络，覆盖：

- 完整分享文案和长链接提取。
- 仿冒域名拒绝。
- `_ROUTER_DATA` 到 `VideoInfo` 的映射。
- `playwm` 分享流到无水印 `play` 原内容流的安全转换。
- 短链跳转和移动端请求头。
- 媒体重定向与流式保存。
- 同名文件不覆盖。
- HTML 风控响应不被误存为 MP4。
- 网页解析 API 的同源校验和下载票据。
- 浏览器附件响应和媒体流代理。
- 嵌入页面的安全响应头与设计规范机械检查。

真实链接仍然应该在发布前人工运行一次，因为页面和 CDN 策略属于程序控制范围之外的外部依赖。

## 常见错误

### `没有找到受支持的 HTTPS 分享链接`

输入中没有链接，链接被截断，或者传入了非域名。重新从复制分享文案并用引号包住整个文本。

### `返回了风控校验页，请稍后重试`

当前 IP 或访问频率触发了页面校验。程序不会绕过验证码。稍后重试，或先确认同一链接能否在普通浏览器无登录打开。

### `作品播放地址不在受信任的媒体域名下`

改变了媒体域名或页面返回了异常数据。应先人工确认新域名确实属于媒体链路，再更新 `mediaHostSuffixes`，不要直接取消域名校验。

### `媒体服务器返回了非视频内容`

播放地址返回了网页或接口错误，而不是视频流。常见原因是链接过期、作品权限变化或媒体网关风控。

### 为什么下载结果不是作品标注的 2K/4K？

作品页面的宽高字段描述源画布，不等于公开分享接口一定提供同规格文件。程序会请求 2160p，媒体服务器再返回该作品公开可用的最高原内容流；如果平台只返回较低档位，程序不能凭空恢复上传母版。真正的上传母版只能由作品创作者从原始存储或平台创作者数据中取得。

### 文件发布失败

确认输出目录可写，并且目标目录与临时文件位于支持硬链接的同一文件系统。程序总是在目标目录内部创建临时文件，因此普通本地磁盘满足该条件。
