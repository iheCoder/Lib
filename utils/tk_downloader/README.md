# 抖音作品下载器

`tk_downloader` 是一个用 Go 实现的公开作品下载工具，同时提供本地网页端和命令行。它接收 App 复制出的完整分享文案或作品链接，支持下载最高可用视频，也支持按发布顺序下载图文作品中的全部图片。

程序不依赖第三方解析网站，不需要登录，也不在代码中维护容易失效的 JavaScript 签名算法。视频会避开分享水印入口；图集会使用公开详情中的无水印展示地址，不使用带水印的 `download_url_list`。

> 详细的设计推导、数据流、安全边界和关键源码说明请阅读 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 使用前提

- Go 1.24 或更高版本。
- Chrome、Chromium 或 Edge。旧版 SSR 页面不需要启动浏览器；当前仅返回作品 ID 的页面会自动使用它。
- 当前网络可以访问分享页、视频 CDN 和图片 CDN。
- 作品无需登录即可公开访问。
- 仅下载自己拥有或已获授权保存的内容，并遵守平台条款及所在地法律。

## 网页端

在仓库根目录启动本地网页服务：

```bash
go run ./utils/tk_downloader -web
```

终端出现下面的提示后，打开 [http://127.0.0.1:17846](http://127.0.0.1:17846)：

```text
网页端已启动: http://127.0.0.1:17846
按 Ctrl+C 停止服务
```

将完整分享文本或作品链接粘贴到输入框，点击“解析作品”：

- 视频作品下载为 MP4，服务端直接流式转发。
- 图文作品会在页面中按原顺序展示，每张图片都有独立下载按钮。

需要修改监听地址时使用：

```bash
go run ./utils/tk_downloader -web -addr 127.0.0.1:18080
```

默认地址只监听本机回环接口。解析成功后生成的下载地址有效十分钟，过期后需要重新解析。

## 命令行

传入完整分享文本并指定保存目录：

```bash
go run ./utils/tk_downloader \
  -o ./utils/tk_downloader/downloads \
  '8.41 复制打开抖音，看看图文作品 https://v.douyin.com/nbByc_Nj9o4/'
```

也可以只传作品链接。省略 `-o` 时，文件保存到当前目录：

```bash
go run ./utils/tk_downloader 'https://v.douyin.com/example/'
```

视频下载成功后会输出文件路径；图集会创建以作者、标题和作品 ID 命名的目录，并输出目录路径和图片数量。同名文件或目录不会被覆盖，程序会自动添加 `(1)`、`(2)` 等后缀。图集中任意一张下载失败时，本次创建的整个目录都会被清理，不会留下看似完整的半成品。

## 构建独立程序

```bash
go build -o ./bin/tk-downloader ./utils/tk_downloader
./bin/tk-downloader -o ./downloads '粘贴完整分享文案'
```

查看所有参数：

```bash
./bin/tk-downloader -h
```

## 支持范围

当前支持：

- 带有 `v.douyin.com` 短链接的完整分享文案。
- `douyin.com/video/{作品ID}` 形式的作品链接。
- 无需登录即可访问的单个视频或图文作品。
- 自动解析作者、标题、作品 ID 和有序媒体列表。
- SSR 缺失作品数据时自动使用本机 headless Chrome/Edge 兼容解析。
- 视频流式下载、图集顺序保存、中文文件名清理和同名保护。
- 网页端与命令行共用同一套解析及媒体校验逻辑。

当前不支持：

- 私密、好友可见或必须登录的作品。
- 直播、合集和批量账号下载。
- 验证码自动处理及登录 Cookie 注入。
- 下载进度、断点续传和多清晰度选择。
- 创作者上传母版。公开分享链路可能只开放转码后的最高可用版本。

## 基本技术说明

解析器采用两级策略。第一层从移动分享页的 `window._ROUTER_DATA` 读取旧版完整视频数据；若页面只有 `itemId`，第二层才启动本机无痕 Chrome/Edge，让官方页面完成动态签名并拦截作品详情响应。详情中的 `images` 非空时，作品被建模为有序图集并优先选择 JPEG 无水印展示地址；否则从 `video.bit_rate` 中选择最高可用的可信 H.264 地址。两条路径最终都产出统一的 `WorkInfo`。

网页端静态资源通过 `go:embed` 编译进可执行文件。页面先调用 `POST /api/resolve` 获取作品类型、媒体数量和短期媒体票据。视频得到一个下载入口；图集中的每张图片得到独立的同源预览地址和下载地址。浏览器不会收到上游媒体地址。

所有出站地址及每一次重定向都会经过 HTTPS 域名白名单校验。网页端还使用同源检查、严格 CSP、请求体上限和随机票据缩小本地服务的攻击面。

## QA 与验证

运行自动化测试和静态检查：

```bash
go test ./utils/tk_downloader
go vet ./utils/tk_downloader
```

测试使用本地 HTTP 服务替代真实网络，覆盖：

- 分享文案提取和仿冒域名拒绝。
- 短链重定向、移动端请求头、旧版 `_ROUTER_DATA` 映射及新版 `itemId` 后备调度。
- 浏览器详情响应的作品 ID 校验、最高 H.264 选择和真实图文结构映射。
- `playwm` 到 `play` 的安全转换。
- 视频与图片的媒体类型校验、流式保存和图集失败回滚。
- 临时文件清理及同名文件、目录不覆盖。
- 网页同源限制、短期票据、MP4 附件响应及逐图预览和下载。
- 嵌入页面的安全响应头及可机械验证的设计约束。

真实链接仍应在发布前人工验证一次，因为页面结构、风控策略和 CDN 行为属于程序控制范围之外的外部依赖。图文回归用例 `nbByc_Nj9o4` 对应作品 ID `7673098271799701430`。同一天的公开 CDN 响应曾返回 1440×2560，最终逐图验收返回 4 张 2160×3840 JPEG，说明公开规格会由上游动态协商；程序保存实际响应，不改写签名 URL，也不伪造尺寸。

## 故障排查

`没有找到受支持的 HTTPS 分享链接` 表示输入中没有完整链接，或者链接域名不在允许范围内。建议重新复制分享文案，并在命令行中用引号包住整段文本。

从聊天工具复制的 Markdown 链接可能形如 `[https://...\\_...](https://...\\_...)`，而多次转发或转义后，下划线前还可能出现多个连续反斜杠。程序会移除链接包装，并把下划线前一层或多层 Markdown 转义统一还原成 `_`，避免把被改写的短链发送给抖音。这些输入形态都有固定回归测试。

`返回了风控校验页` 表示当前 IP、访问频率或页面策略触发了校验。程序不会自动绕过验证码，可以稍后重试，并先确认同一链接能否在普通浏览器中无登录打开。

`当前分享页需要浏览器解析，但未找到 Chrome、Chromium 或 Edge` 表示新版页面没有在 SSR 中附带视频数据，且程序无法找到可执行浏览器。安装任意一种受支持浏览器后重新启动程序即可。

新版页面首次解析通常比旧版慢几秒，因为程序只在需要时启动一次隔离的 headless 浏览器。并发解析会排队，避免一次生成过多浏览器进程。

`作品播放地址不在受信任的媒体域名下` 表示页面出现了尚未确认的媒体域名或异常数据。应人工验证新域名的归属后再更新白名单，不要直接移除地址校验。

`媒体服务器返回了不匹配的内容` 表示媒体入口返回了 HTML、JSON 或与作品类型不符的响应。常见原因包括作品权限变化、地址失效或上游风控。

作品页面声明的画布尺寸不等于公开分享链路一定提供同规格文件。程序请求最高偏好档位，但不能从较低清晰度的公开转码文件恢复创作者上传母版。
