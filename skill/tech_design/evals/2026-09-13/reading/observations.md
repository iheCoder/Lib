# 六份独立盲读的观察

每位读者使用新上下文，只看一条预先选定的匿名回答，不看原题、前文、Skill 或评分。以下是主代理核对原文后的解释，不是读者自报的人类理解成绩，也不把缺口数量当总分。

| 输入 | 实际文本阶段 | 读者能提取什么 | 缺口应怎样解释 |
|---|---|---|---|
| R01：names baseline 第一次，第三轮 | 附外部前提的完整设计文档 | 本地读取、后台全量获取、事务发布、名称过期及选型原因 | 所列缺口是 CRM 分页、删除与源数据时间尚未核实；作者已明确列作依赖，不是仅有术语而没有解释 |
| R02：export baseline 第一次，第二轮 | 对指定交错的后续回答 | V41 保持不变、执行资格限制写入、下载再次鉴权 | 单条回答没重述扫描器恢复过程；首轮已有对应说明，不能据此判整段对话缺少设计 |
| R03：small skill 第一次，第一轮 | 推荐机制与一个实现前提问题 | 单项保存、事务读取最新集合、提交生效、先鉴权再分组、整体设置覆盖风险 | 读者没有报告关键过程缺口 |
| R04：export skill 第一次，第二轮 | 对指定交错的后续回答 | 新旧执行身份、成功结果保护、撤权后拒绝下载 | 单条回答没重述待投递事项由谁接手；首轮已有后台持续投递说明，不是新增文字不清楚证据 |
| R05：small baseline 第一次，第一轮 | 完整建议 | 单项保存、数据库提交顺序、稳定分组和必要设置检查 | 读者没有报告关键过程缺口 |
| R06：names skill 第一次，第三轮 | 暂停定稿、追问接口事实 | 能复述先读第一页、CRM 删除导致位置前移、后续页漏读、完整替换后名称消失的因果链 | 读者明确指出保证尚未确认；这条文本不是完整文档，不能与 R01 直接比较阅读速度或文档完整度 |

这次盲读提供了可查原文的复述证据，也暴露了测量边界：对话后续回答合理依赖前文，单条盲读会制造上下文缺口；读者的模型能力可能比普通开发者强。结果不足以断言 Skill 降低了真人认知负担，也不能据此宣称双方真人可读性相等。

本轮可读性最终评分仍由看完整轨迹的模型依据冻结规则完成，盲读用于补充解释，不回填成“真人理解率”。若要测用户最关心的实际读懂程度，下一步应以相同阶段的文档给真实普通开发者做匿名复述，记录理解错误和需要追问的地方；不能继续用模型复述次数替代这项证据。
