建议以 PostgreSQL 中的任务记录作为唯一状态依据：创建时固定数据版本，后台按任务流式生成 CSV，每次执行使用独立对象，只有持有当前执行权的实例才能把结果登记为完成。下载由平台入口逐次鉴权并代理传输。

这份设计需要守住三个约束：同一任务始终读取同一数据版本；任务最多公布一个文件，完成后不能被重试改写；撤权只影响之后的下载鉴权，不改变任务计算或完成状态。

**接口与任务归属。** 建议提供以下接口，返回值中的时间均由服务端生成：

| 接口 | 行为 |
| --- | --- |
| `POST /reports/{report_id}/exports` | 创建任务，返回 `202`，包含 `task_id`、`data_version`、`status`、`expires_at` |
| `GET /exports/{task_id}` | 返回状态、固定的数据版本、有效期；完成后返回平台下载入口，失败时返回可公开的失败原因 |
| `GET /exports/{task_id}/download` | 本次鉴权通过且任务完成、未过期时，返回 CSV 文件流 |

本稿按“任务属于创建者，只能由创建者查询和下载”设计，同时校验租户边界。导出权限被撤销后，创建者仍可以查询任务状态，但不能通过下载鉴权。这符合撤权不改变任务状态的要求。如果企业内需要共享下载，需要另行明确任务可见范围；不能仅凭知道任务号就允许访问。

有效期暂按创建时间起算，由服务端配置，创建响应返回确定的 `expires_at`。未完成任务到期后停止重试；完成任务过期后保留完成记录，下载返回过期。若产品希望“完成后再保留若干天”，需要调整有效期计算及数据版本的保留约定，不应由实现自行混用这两种口径。

**持久化信息。** 可以用一张 `export_tasks` 表承载当前流程，无需另建完整的执行历史系统。

| 信息 | 建议字段与用途 |
| --- | --- |
| 身份与输入 | `id`、`tenant_id`、`creator_id`、`report_id`、`data_version`，以及确实影响本次输出的报表查询定义 |
| 生命周期 | `status`、`created_at`、`expires_at`、`completed_at`、`last_error_code` |
| 执行控制 | `attempt_no`、`lease_until`、`next_attempt_at`；执行代次同时用于阻止旧实例提交 |
| 已公布结果 | `object_key`、`file_size`、`checksum`、`row_count`；完成前为空，完成后不可替换 |

状态为 `QUEUED`、`RUNNING`、`COMPLETED`、`FAILED`。到期作为独立的时间判断，不把已完成任务重新写成失败。`COMPLETED` 不存在退出路径；失败重试发生在进入最终 `FAILED` 之前。

数据库约束应保证完成状态具有完整结果信息。所有更新执行状态的语句都要限制原状态，不能用一个无条件的任务更新接口覆盖终态。

如果报表的列定义、筛选条件或排序会变化，创建时还需要固定这些查询输入，或保存其不可变定义版本。固定数据版本不能同时保证可变报表定义也被冻结；不影响导出内容的页面配置无需保存。

**创建与可靠调度。** 创建接口先验证登录身份、任务归属所需的租户信息，再调用权限服务检查该报表的导出权限。鉴权拒绝时不创建任务；鉴权接口失败时返回可重试错误，不默认放行。

鉴权通过后，向数据服务选取一个已经发布的版本，把版本和任务一起写入 PostgreSQL，事务提交后才能向页面返回成功。数据服务随后发布新版本不影响本任务。任务创建成功后的撤权不触发任何计算取消逻辑。

数据库与队列不做跨系统事务。本期采用“任务表保底、队列唤醒”的方式：任务落库后立即尝试投递任务号，同时由后台扫描器周期性投递到期可运行的 `QUEUED` 任务及租约已过期的 `RUNNING` 任务。这样即使落库后进程退出、队列发送失败，也能重新唤醒任务。扫描器不把任务改成已领取，真正的执行权由消费者争抢数据库记录决定。

扫描索引覆盖状态、下次执行时间和租约截止时间。扫描按批次执行，重复消息由领取逻辑过滤。队列消息只携带任务号；版本、身份和查询参数均从数据库读取，避免重投消息夹带不同输入。

**领取、续租与重试。** 消费者使用短事务锁定任务行，检查任务未过期，且满足以下任一条件：等待执行并已到重试时间，或者正在执行但租约已过期。随后递增 `attempt_no`，设置 `RUNNING` 和新租约，提交事务。多个实例同时领取时，只有一个实例成功；生成文件期间不持有数据库事务或行锁。

执行实例定期续租，续租语句必须同时匹配任务号、`RUNNING`、本次 `attempt_no`，并要求租约尚未过期。租约一旦失效，旧执行不能通过续租恢复身份。续租失败或无法确认时停止继续处理，并且不得公布结果。

租约只能减少重复计算，不能证明旧进程已经停止。因此，提交完成、登记重试、写最终失败都必须检查执行代次和租约，旧执行的任何后续操作都不能覆盖新执行。

可恢复错误，例如数据服务超时、对象存储短暂不可用，使用指数退避和抖动重新排队。重试次数、最长退避和租约参数作为运维配置，不在设计中硬编码经验数字。确定不可恢复的错误，或重试预算耗尽，进入 `FAILED`。消息重复到达但未获得执行权，不计作一次失败尝试。

重试时仍读取任务最初记录的版本，绝不能自动切换到最新版本。撤权不属于执行错误，后台计算不反复调用创建者的导出鉴权。

本期重试从头生成文件，不实现断点续导。几十分钟的任务可能因此重复读取数据，但避免了页进度、CSV 字节边界和分段上传恢复之间的额外一致性问题。后续只有在实际重算成本不可接受时再增加检查点。

**分页和文件生成。** 每次向数据服务请求分页时，明确传入同一个 `data_version` 和固定查询输入。分页必须具有稳定游标，或基于唯一排序键的稳定顺序；不可变版本并不自动意味着无排序的分页不会漏行、重行。评审时需要核实数据服务当前分页契约，如无法保证稳定遍历，这是实现前必须补齐的依赖。

采用“取一页、编码一页、写出一页”的流水线，通过对象存储 multipart upload 上传。内存上限由单页数据与有界上传缓冲决定，不随总行数增长；上传端变慢时暂停拉取下一页。整个流程同时累计文件大小、行数和校验值。失败后终止本次 multipart upload，存储侧也配置未完成上传的清理。

CSV 统一使用固定列顺序和编码约定，正确转义逗号、双引号和换行；空结果输出表头。编码、空值表示、时间格式及面向电子表格的公式文本处理，需要作为平台导出格式约定固定下来，并在同一任务的重试中保持一致，不能由不同实例自行决定。

**结果只公布一次。** 每次执行使用独立且不可覆盖的对象路径，例如 `exports/{task_id}/{attempt_no}/{random_id}.csv`。执行期间的对象不提供给页面，所有对象均为私有。生成结束后的顺序为：

1. 完成对象上传，并确认对象已经可以读取，文件大小和校验信息符合本次生成结果。
2. 在一个数据库原子更新中，同时写入对象标识、文件元信息、`completed_at` 和 `COMPLETED`。
3. 更新条件必须包含 `RUNNING`、本次执行代次、租约仍有效以及任务尚未过期。

对象上传成功与数据库提交之间不要求原子事务。数据库提交前，页面只能看到未完成；提交后，页面只能读取已经登记的那个对象。对象路径唯一且禁止覆盖，因此迟到的执行即使上传成功，也只能留下另一个未公布的对象。

若数据库更新结果因网络超时而不确定，执行实例必须重新读取任务记录判断是否已经提交，不能直接删除刚上传的文件，也不能直接把任务记为失败。若任务已经完成，且登记的是本次对象，就按成功结束；若由其他执行完成，则本次对象没有资格替换结果。

完成后收到重复消息、发生权限变化或有旧执行回报失败，均不修改完成记录。平台查询接口只读数据库，不根据队列、工作进程或当前权限临时推导一个新状态。

**下载与撤权。** 下载接口依次确认用户身份和任务归属、任务完成且未过期，然后同步调用权限服务检查该报表的当前导出权限。必须使用这次调用得到的鉴权结果，不复用创建时权限，也不使用可能落后的本地允许缓存。鉴权服务不可用时拒绝本次下载并返回可重试错误。

鉴权通过后，由后端读取任务登记的对象并流式返回浏览器。不能把可绕过平台鉴权的长期下载链接或对象存储签名 URL 发给页面；仅在签发 URL 时鉴权，无法保证后续每次取文件都重新检查权限。下载响应禁止共享缓存，平台下载入口也不能被 CDN 直接命中后绕过鉴权。

并发撤权按题目给出的权限服务语义处理：撤权提交成功后才发起的鉴权调用必然被拒绝；如果本次调用返回允许，这一次传输可以继续完成，不在传输中途反复鉴权。断线后的重试或新的 Range 请求属于新的下载请求，需要重新鉴权。

对象读取失败应返回下载错误并记录告警，不能把任务改回运行中，或现场重新生成另一个文件。对象存储的保留和访问策略必须保证已公布文件在任务有效期内不会被生命周期规则提前删除或覆盖。

**到期与回收。** 到期后禁止领取新执行、提交新结果和接受新下载。已公布对象的物理删除必须晚于有效期，并避免中断已经获准开始的文件传输。

有效期内不回收该任务下已经完整上传的尝试对象，简化清理与完成提交之间的竞争。到期后可以按任务前缀回收文件；对于已开始的下载，需要确认对象存储是否保证打开的读取流不受删除影响。若没有该保证，平台必须提供活动下载保护，清理器在活动读取结束后才能删除；不能用一个未经证明的固定短延迟代替这个约束。

未完成 multipart upload、未公布的完整对象和已公布对象分别监控。过期任务可能仍有失去执行权的进程迟到上传，清理扫描需重复覆盖这些前缀；迟到上传无论是否完成，都不能通过数据库的过期和执行代次检查。

**评审验证重点。** 应通过可控暂停、超时和故障注入验证以下场景，重点观察数据库最终记录和实际下载内容：

| 场景 | 必须得到的结果 |
| --- | --- |
| 导出中发布新版本 | 每次分页仍使用原版本，CSV 不混入新版本数据 |
| 同一消息被两个实例同时处理 | 只有一个实例获得当前执行权；重复消息不会创建新任务 |
| 旧执行租约过期，新执行完成后旧执行恢复 | 完成状态和对象标识保持不变，旧执行无法提交成功或失败 |
| 对象上传完成后进程退出 | 不出现无文件的完成状态；任务恢复后最多公布一个对象 |
| 完成事务成功，但响应丢失 | 恢复后识别已有结果，不删除已公布文件或重新覆盖它 |
| 任务提交后尚未发消息即退出 | 扫描器最终投递并恢复执行 |
| 运行中撤权、完成后撤权 | 计算和完成状态不受影响；撤权提交后发起的下载鉴权拒绝 |
| 鉴权通过后立即撤权 | 已获准的这次传输可以完成，下一次下载重新鉴权 |
| 大数据、慢存储及特殊 CSV 内容 | 内存保持有界；无漏行、重行，CSV 可正确解析 |
| 临近过期开始下载，同时触发清理 | 已接受的传输不因文件回收被中断；过期后的新下载被拒绝 |

运行指标至少覆盖等待时长、执行时长、重试次数、租约丢失、最终失败、下载错误及未回收对象数量。日志关联任务号和执行代次，避免记录报表内容。

评审需要确认的剩余业务口径是任务归属范围、有效期起算点和 CSV 格式；技术依赖是分页的稳定遍历保证，以及对象删除对进行中读取的语义。其余实现可以围绕上述单一任务记录、执行租约、独立对象和原子完成更新展开。
