# 技术设计 Skill 行为质量补充评估

## 1. 当前结论与要补的证据

上一轮主要检查正确性、修正和确认边界，不能用 4/6 与 5/6 断言 Skill 净收益为负。部分题目直接提醒了“解释概念”等目标行为，会减弱对 Skill 作用的观察。本轮冻结同一 Skill，用新的自然需求，比较可读性、范围控制、必要复杂度、合理方案、约束变化和具体交错推演。旧结果不改写，新增维度不追认成旧轮预设标准。

本文件、题目、评分规则和校准答案在实际对话生成前固定。固定每题每条件两次，共 12 次独立尝试、24 个自然回复。样本少，只看具体现象和是否值得继续研究，不设上线通过率。

## 3. 六类检查角度

| 角度 | 计划覆盖 | 做法与边界 |
|---|---|---|
| 已知要求与职责 | 已覆盖 | 自然语言、设计范围、必要机制分别评分；不奖励篇幅或章节齐全 |
| 状态与变化 | 已覆盖 | 名称查询约束变化后修正；导出成功状态、版本与权限是不同事实 |
| 输入与边界 | 部分覆盖 | 小功能、外部读取取舍、长任务三类；不是广泛业务分布 |
| 外部交互 | 部分覆盖 | CRM 与鉴权依赖的纸面机制；不运行真实服务 |
| 时间与并发 | 部分覆盖 | 首轮自主发现与二轮明确 A/B/C 时序分开；检查的是设计推演，不是已执行并发实现 |
| 原有能力与回归 | 部分覆盖 | 两条件同题两次，小功能观察无端复杂化；旧评估保留但不全部重跑 |

## 5. 没有证明什么

盲读者和评分者仍是模型，没有真人理解率、阅读耗时或人工校准。两位评分者先通过人工构造的明确正反例检查，再各评一组完整配对，不能排除共同盲区和尺度差异。工具接口未暴露精确底层模型版本/采样参数；基线仍有共享系统指令的可读性与最小化要求，不能解释成毫无限制的裸模型。

被测尝试采用新上下文和指定文件边界，实际仍共享文件系统；没有完整底层工具轨迹来机械证明无越界读取。报告只评价实际保存的设计对话。没有实施真实系统，不把方案推演正确当作性能或并发代码验证。

## 6. 执行与交付

先完成独立风险复核和评分器校准，冻结输入与版本，再运行全部固定尝试。对匿名输出分别评分、做六份盲读，核验引用和哈希后报告每维结果、具体例子和未证明部分。不根据谁输谁赢选择样本，不追加引导救分，不修改 Skill。脚本整理材料和检查证据，不冒充模型运行器；重新生成需按 runner-contract.md 建立新尝试。
