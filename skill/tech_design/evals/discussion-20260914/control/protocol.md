# 预先确定的实验方法

来源任务：01a09f6f-33ba-7d52-b260-d606b46562d1（local）。2026-09-14 当前需求文件与原型快照，结合会话已确认的业务勘误；不声称恢复了历史某一时刻的全部上下文。

目标：观察当前 skill 能否主动识别并展开常用完整读写链、正文内参数模板、分类内排序的影响范围；根据实际遗漏提出候选指引，以相同输入对照。

每个版本两个全新上下文，每次最多四轮；代理继承父模型，不主动覆盖模型或推理强度。输入包含完整原型，原型实现只作交互材料，不代表生产设计。不给评分标准、期望难点、历史助手设计、用户关于设计缺陷的评价。

第 1 轮：按 input/request.md 自然开始设计。
第 2—4 轮：仅确认已明确解释的推荐，表示继续；如模型问业务事实，只从冻结需求与勘误回答。没有明确依据的事实告知未知，允许显式假设。不能主动点名未被模型提出的主题，不能补入故障场景暗示。
默认续轮回复：你已经解释清楚的建议可以按推荐继续；尚未展开的设计还没有确认。请按你认为合适的顺序继续讨论。规模目前没有可靠实测数据，需要时请明确假设。
如模型在四轮内生成最终文档，照实记录，不额外引导补题；未到某议题只记观察窗口未覆盖，不推断永远不会讨论。

判据（定性分别评估，不用总分掩盖差异）：
- 发现重点：能解释为何值得讨论，不仅提及术语。
- 常用：从使用记录到窗口/门槛/自然日计算、当前有效与可见过滤、排序/截取/分页相互关系，涉及查询成本和可配置窗口；区分部分与完整链路。
- 参数模板：编辑、存储、回显、填写/选择、自由编辑、最终发送的表示和语义，讨论真实选择与限制；普通字符串替换一句话不算充分。
- 排序：写入范围、成本随集合增长、并发冲突；尤其是否解释对非排序编辑、删除、跨分类移动的影响和锁等待，是否说明取舍。
- 互动：提出可判断的方案与代价后留出反馈机会；不把局部同意扩张为全部确认；无须每轮都新发现所有问题。
- 主次与成本：统计不能拖累对话；不因保证局部正确而忽略延迟、依赖、写放大、其他操作受限。
- 适度：不编造现场数据，不强制不必要方案/基础设施，不通过增加大量通用清单碰巧命中。

候选补丁仅基于已观察遗漏，在控制区记录差异后冻结。相同初始输入、相同轮数和回复策略，两个新上下文复跑。评分包不标版本；真实回答保留且注明轮次，不以脚本关键词命中替代语义判断。

限制：这是同一实际需求下的有限样本、离线设计讨论，不是线上查询、数据库锁或性能实测。输入已包含晚期确认的业务前提，因此不能据此证明最初完全未澄清时也会自主问出这些前提。不给完整源代码，不能证明对现有代码的侦察能力。没有无 skill 组，不能量化 skill 相对模型本身的净收益。
