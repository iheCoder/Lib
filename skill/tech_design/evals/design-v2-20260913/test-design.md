# 技术设计 Skill 候选版对照：运行前设计

本轮检查新增规则能否使设计对话更可靠，同时保住原有的易懂、范围控制、合理取舍和简单题直接收敛。比较旧版、候选版和不加载此 Skill 三组，同一模型设置、同一业务输入，每题每组运行两次。共五题、30 条独立轨迹、54 份回答。这里只运行设计对话，不创建真实工单、公告或报告。

## 实际检查的五个场景

1. **报告生成与通知**：用户重试同一次申请，后台重复消费，通知已经创建但响应丢失。正确设计要让申请可找回、报告产物唯一、通知可确认，不能因通知未知重算已确认的报告。允许故障后重复计算，最终业务产物只有一份即可。首轮观察申请身份与可靠受理，第二轮观察明确时序下的恢复。
2. **搜索索引与历史快照**：一分钟内上万个版本，旧构建晚于新构建完成。正确设计要限制旧任务积压，并在真正发布时阻止版本倒退。第二轮加入必须逐份保留的快照，检查是否错误地把所有任务都套成“只留最新”，以及共享工作池是否会饿死某类已受理任务。
3. **Agent 创建工单**：平台已支持业务请求号去重和查询。创建成功却超时、重启查询到工单后，模型修复 JSON 又发起创建。正确设计要沿用原申请身份和已确认事实，由执行代码阻止重新创建；原请求已授权，不应增加常规审批。
4. **批准后延迟发布公告**：批准绑定正文、对象和位置，执行时对象仍须允许接收。恢复后模型改正文和对象，同时客户开关改变。正确设计要守住批准范围，在实际写入处保持接收条件，并沿用仍有效的批准；第二轮允许逐对象执行，不因无关资料变化整批重审批。
5. **个人显示偏好**：已有表、局部更新接口、登录用户和明确的保存顺序。正确设计应直接复用这些能力，保存成功再切换本页，失败保留原显示。用它检查新规则是否反而增加队列、审批、冲突机制或多余提问。

每题具体业务规则和允许的实现例子在冻结题目中。例子不是正确答案穷举；满足同一业务约束的其他机制同样可通过。先后两轮分别记录，第二轮明确提示后才补出的内容不算首轮发现。首轮合理等待决定的未展开项记为未覆盖，不混算成明确错误。

## 六个检查角度的计划范围

| 角度 | 计划覆盖状态 | 对应现实风险与剩余边界 |
| --- | --- | --- |
| 业务承诺与输入输出 Contract | 部分覆盖 | 受理可恢复、申请唯一、批准范围、保存反馈；没有覆盖全部业务领域或真实接口实现。 |
| 状态和事实 State | 部分覆盖 | 报告/通知分离、工单未知结果、获批内容与当前资格、历史任务保留；未测试长对话状态漂移或全部状态来源冲突。 |
| 输入与边界 Partition | 部分覆盖 | 简单/异步/Agent、同次重试/新申请、可取代/必须保留；没有覆盖外部服务缺少去重能力、规模随机分布或全部 Agent 任务。 |
| 组件协作 Interaction | 部分覆盖 | 模型与宿主、工作进程与外部服务、审批与门户写入；无真实工具执行、恶意外部内容或过期记忆输入。 |
| 时间与并发 Time-Concurrency | 部分覆盖 | 固定的多参与者交错、响应丢失、重启、检查写入竞态、队列积压；文字推演不能替代并发测试或容量压测。 |
| 既有能力 Regression | 部分覆盖 | 三组同题检查可读性、范围、最小复杂度、取舍与直接收敛；本轮不完整重跑此前所有云盘/财务/导出案例，也没有真人理解实验。 |

## 如何产生与判断证据

题目由未读取 Skill 的独立上下文编写；另一评审先只读旧版列风险，再揭示候选和题目审查公平性。两名评分员在真实回答生成前先评八个合成校准例，各自全部匹配预设判断。校准只是确认明显正反例能够区分，不是人类评分一致性的证明。

每条被测轨迹在新上下文开始，只得到当前用户轮次，以及该组有权加载的 Skill 快照。后续轮次沿用同一轨迹。旧版和候选版的文件名称对被测者一致，不提供“新旧”标签。不加载 Skill 的组不获得额外风格辅导。输入不要求罗列方案、不提示评分维度。所有组仍共享宿主的全局指令；这是指令约束的上下文隔离，不是文件系统或运行环境安全隔离。

每份原始回答完整归档，再按与条件无关的编号交给评分员。若原文显式自报加载 Skill，只能在匿名副本移除该句自报，并登记被移除内容；不得修改设计。原文始终保留。评分员根据逐字引文解释机制、错误及其后果，同时评解释充分性、设计范围、必要复杂度、真实方案取舍和决策状态。评分分歧保留并核对，不用总分隐藏错误。

不挑选最好的一次，不因失败重跑。固定题目、两组快照、判据和校准材料均在生成回答前记哈希。原文完整性与评分引文由脚本核对。两个模型评分员不能证明普通开发者真的看懂；所有结论限制为本轮固定题目和设置下的行为证据。

## 不准备借此声称的收益

本轮没有直接测上下文注入、过期记忆、循环预算耗尽、未知外部能力下的保证边界、较长讨论中的假设撤回。五题与本次修改方向相关，不能称为完全未见领域的泛化检验。即使候选表现较好，也只支持具体场景收益；若三组相同，就报告未观察到增益。Skill 结构校验与行为 eval 分开报告。
