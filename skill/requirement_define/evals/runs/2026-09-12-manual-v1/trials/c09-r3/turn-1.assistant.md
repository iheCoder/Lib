当前需求的核心业务规则已经明确，可以整理为以下需求文档。

**背景与目标**

为线下活动增加用户自主报名和取消功能，减少工作人员手工登记。已登录用户可以在活动开始前为自己报名，并取消自己的有效报名。

**报名与取消规则**

| 场景 | 业务行为 |
|---|---|
| 用户未登录 | 不能报名或取消报名 |
| 活动未开始，用户没有有效报名且有剩余名额 | 可以报名；报名成功后产生一份有效报名，占用一个名额 |
| 用户已有该活动的有效报名，再次报名 | 保留原有效报名，不新增有效报名，不额外占用名额 |
| 名额已用完 | 不能新增报名 |
| 活动未开始，用户有自己的有效报名 | 可以取消；取消成功后该报名不再有效，立即释放一个名额 |
| 用户没有该活动的有效报名 | 不能取消，剩余名额不变 |
| 用户取消后重新报名 | 活动未开始且仍有名额时可以重新报名，成功后重新占用一个名额 |
| 活动已开始 | 不能报名，也不能取消报名 |
| 报名或取消失败 | 本次操作不改变原报名及剩余名额 |

**必须保持的业务约束**

- 每名用户在每场活动中最多有一份有效报名，只能为自己报名或取消自己的报名。
- 一份有效报名占用一个名额；成功取消只释放该报名占用的一个名额。
- 多人同时争取剩余名额时，成功报名的人数不能超过剩余名额。
- 同一用户重复或同时提交报名、取消操作，也必须遵守上述规则，不能重复占用或重复释放名额。
- 取消释放的名额可供符合条件的用户报名；原用户重新报名时不保留优先权。
- 失败不改变本次操作涉及的报名和名额，但不妨碍其他用户成功操作引起名额变化。

**与现有产品的衔接**

活动是否开始，沿用现有产品提供的开始时间及其判断规则。本次不修改时间规则，也不支持活动开始时间变更。

**本次范围外**

候补、支付、代报名、通知，以及新增管理员代用户取消报名的入口。

**主要验收场景**

1. 用户在活动开始前首次报名成功，形成一份有效报名，剩余名额减少一个。
2. 已报名用户重复提交报名，有效报名仍只有一份，剩余名额不再减少。
3. 仅剩一个名额时，多名用户同时报名，最多一人成功。
4. 用户在活动开始前取消成功，报名不再有效，名额立即增加一个；再次取消不能重复释放名额。
5. 取消后，有名额且活动未开始时可以重新报名；名额已被占满或活动已开始时不能重新报名。
6. 活动开始后，报名和取消均不能成功，已有报名及名额不因这些操作改变。
7. 报名或取消失败时，不出现“报名失败却占用名额”或“取消失败却释放名额”的结果。
