本次需求是为线下活动提供用户自助报名和取消能力，减少工作人员手工登记。现有描述已足够明确，可整理为以下业务需求，供后续设计、开发和测试使用。

1. **使用对象与权限**

   已登录用户可以为自己报名，并取消自己的有效报名。每位用户在同一场活动中最多有一份有效报名。

2. **报名规则**

   活动开始前，用户没有该活动的有效报名，且活动仍有剩余名额时，可以报名。

   报名成功后，用户获得一份有效报名，占用一个名额。重复报名不能新增有效报名，也不能额外占用名额。

   名额用完或活动已经开始时，不能报名。

3. **取消与重新报名**

   活动开始前，用户可以取消自己的有效报名。取消成功后，该报名不再有效，并立即释放一个名额。

   用户没有有效报名时，不能取消；活动已经开始时，不能取消。

   取消后，只要活动尚未开始且仍有名额，用户可以重新报名。释放的名额不为原用户保留。

4. **失败与同时操作**

   报名或取消失败时，原报名和剩余名额保持不变，不得出现报名失败却占用名额、取消失败却释放名额等结果。

   多人同时争取有限名额时，成功报名人数不能超过可用名额。同一用户同时或连续重复操作，也必须遵守“一人一场最多一份有效报名”的限制，同一份报名不能重复占用或重复释放名额。

   失败操作不得改变报名和名额；其他用户成功操作引起的正常名额变化不受此限制。

5. **活动时间**

   活动是否开始，沿用现有产品提供的开始时间及时间规则。报名和取消均仅允许在活动开始前完成。

   本次不修改时间规则，也不支持活动开始时间变更。

6. **范围外**

   本次不包含候补、支付、代报名或通知，也不新增管理员代用户取消报名的入口。

主要验收场景如下：

| 场景 | 预期结果 |
|---|---|
| 活动未开始、有名额，用户尚无有效报名 | 报名成功，产生一份有效报名，剩余名额减少一个 |
| 用户已有有效报名，再次报名 | 不新增有效报名，不额外占用名额 |
| 名额已用完，用户尝试报名 | 不能报名，原报名及名额不因该操作改变 |
| 活动未开始，用户取消有效报名 | 取消成功，报名不再有效，立即释放一个名额 |
| 用户没有有效报名，尝试取消 | 不能取消，不释放名额 |
| 用户取消后重新报名 | 按当时的活动时间和剩余名额判断，符合条件即可成功 |
| 活动已经开始，用户尝试报名或取消 | 均不能成功，原报名及名额不因该操作改变 |
| 多名用户同时争取最后一个名额 | 最多一人报名成功 |
| 同一用户重复提交报名或取消 | 不产生多份有效报名，不重复占用或释放名额 |
| 报名或取消失败 | 该操作不改变原报名及剩余名额 |
