**线下活动自主报名与取消**

为减少工作人员手工登记，支持已登录用户在活动开始前为自己报名、取消报名，并在取消后满足条件时重新报名。

**核心业务规则**

| 场景 | 条件与预期结果 |
|---|---|
| 报名成功 | 用户已登录，活动尚未开始，用户在该活动没有有效报名，且仍有剩余名额。成功后产生一份有效报名，占用一个名额。 |
| 重复报名 | 每人每场活动最多有一份有效报名。已有有效报名时，再次报名不得新增有效报名或额外占用名额。 |
| 名额已满 | 不允许新增报名，已有报名和剩余名额保持不变。 |
| 取消成功 | 用户在活动开始前取消自己的有效报名。成功后该报名不再有效，立即释放一个名额。 |
| 无有效报名时取消 | 不允许取消，报名和剩余名额保持不变。重复取消不得重复释放名额。 |
| 取消后重新报名 | 活动尚未开始且仍有名额时，用户可以重新报名；原名额不为该用户保留。 |
| 活动已经开始 | 不再允许报名或取消。开始时间及是否已开始的判断沿用现有产品规则。 |
| 报名或取消失败 | 本次操作不得改变原报名和剩余名额。 |

用户只能操作自己的报名。未登录用户不能完成报名或取消操作。

**重要场景与验收要点**

- 多名用户同时争抢最后一个名额时，最多一人新增有效报名，不得超出活动名额。
- 同一用户连续或同时提交多次报名时，最多保留一份有效报名，只占用一个名额。
- 同一份有效报名被多次请求取消时，最多释放一个名额。
- 取消成功后，释放的名额立即可供符合条件的用户报名。
- 用户取消后，如果名额已被其他用户占用且活动已满，则不能重新报名。
- 报名失败不得出现“没有有效报名却扣减了名额”；取消失败不得出现“报名仍有效却释放了名额”。
- 操作失败只要求该次操作不产生变更，不影响其他用户正常报名或取消所带来的名额变化。

**范围与现有产品衔接**

本次不包含候补、支付、代报名或通知，也不新增管理员代用户取消的入口。活动开始时间使用现有产品提供的数据，不修改时间规则，不支持活动开始时间变更。

具体页面布局、提示文案及技术实现留到后续设计，不影响上述业务规则的确定。
