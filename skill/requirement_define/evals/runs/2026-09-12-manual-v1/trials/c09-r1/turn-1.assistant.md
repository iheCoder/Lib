**线下活动自主报名与取消需求**

**背景与目标**

为线下活动增加自主报名和取消能力，让已登录用户自行管理本人的报名，减少工作人员手工登记。

**报名与取消规则**

“有效报名”指用户报名成功且尚未取消的报名，每份有效报名占用一个名额。

| 操作 | 允许条件 | 成功后的结果 |
|---|---|---|
| 报名 | 用户已登录、活动尚未开始、本人没有该活动的有效报名，且活动仍有名额 | 为本人建立一份有效报名，剩余名额减少一个 |
| 取消 | 活动尚未开始，用户拥有该活动的有效报名，且操作对象为本人报名 | 该报名不再有效，立即释放一个名额 |
| 重新报名 | 本人已取消报名，且再次满足报名条件 | 恢复参与资格，占用一个名额，仍须遵守每人每场最多一份有效报名的限制 |

补充约束：

- 每人每场活动最多有一份有效报名。重复报名不得新增有效报名或多占名额。
- 名额用完时不能报名。取消后释放的名额可以用于后续报名，原报名用户重新报名时也须以当时是否还有名额为准。
- 没有有效报名时不能取消；重复取消不得再次释放名额。
- 活动一旦开始，用户不能再报名，也不能取消报名。
- 报名或取消失败时，该操作不得改变原报名情况或剩余名额。

**时间与权限边界**

活动是否已经开始，沿用现有产品提供的活动开始时间及时间判定规则。本次不修改时间规则，也不支持活动开始时间变更。

用户只能为自己报名或取消自己的报名。本次不新增管理员代用户取消的入口。

**关键验收场景**

| 场景 | 预期结果 |
|---|---|
| 未登录用户尝试报名 | 不能建立报名或占用名额 |
| 活动未开始且有名额，用户首次报名 | 成功建立一份有效报名，占用一个名额 |
| 已有有效报名的用户重复提交报名 | 有效报名仍只有一份，不额外占用名额 |
| 多人同时争取最后一个名额 | 最多一人报名成功，不得超额报名 |
| 同一用户同时提交多次报名 | 最多建立一份有效报名，占用一个名额 |
| 用户在活动开始前取消有效报名 | 取消成功，立即释放一个名额 |
| 用户没有有效报名或重复提交取消 | 不能再次取消，不额外释放名额 |
| 取消后重新报名 | 活动未开始且仍有名额时可以成功；否则不能报名 |
| 活动已经开始后尝试报名或取消 | 操作不成功，原报名及名额不因该操作改变 |
| 报名或取消失败 | 不出现报名改变而名额未对应改变的部分成功结果 |

**本次范围外**

候补、支付、代报名、通知、管理员代用户取消入口，以及活动开始时间变更。
