本次需求的核心业务规则已明确，可整理为以下需求文档，供后续设计、开发和测试使用。

**背景与目标**

为线下活动增加自助报名和取消功能，让已登录用户自行管理本人的报名，减少工作人员手工登记，同时保证报名不重复占用名额、不超出活动容量。

**报名与取消规则**

| 场景 | 业务规则与结果 |
|---|---|
| 首次报名 | 活动尚未开始、仍有名额且本人没有有效报名时，已登录用户可以为自己报名；成功后产生一份有效报名，占用一个名额。 |
| 重复报名 | 每人每场活动最多有一份有效报名；已有有效报名时，再次报名不能新增有效报名或多占名额。 |
| 名额已满 | 不能报名，原报名和剩余名额保持不变。 |
| 活动已开始 | 不能报名，也不能取消报名。 |
| 取消报名 | 活动开始前，用户可以取消自己的有效报名；成功后该报名不再有效，并立即释放一个名额。 |
| 没有有效报名时取消 | 不能取消，不改变报名情况或剩余名额。 |
| 取消后重新报名 | 活动尚未开始且仍有名额时，可以重新报名；取消不保留原名额。 |
| 报名或取消失败 | 原报名和剩余名额均保持不变，不得出现只改变其中一项的结果。 |

用户只能为自己报名或取消自己的报名，不能操作他人的报名。

**重要边界与验收要求**

- 多名用户同时争取有限名额时，成功报名人数不能超过可用名额。例如只剩一个名额时，最多一人报名成功。
- 同一用户重复提交报名时，最多形成一份有效报名、占用一个名额。
- 同一份有效报名重复提交取消时，最多释放一个名额；已无有效报名后的取消不能再次释放名额。
- 取消成功释放的名额可用于后续报名，仍须满足活动尚未开始的条件。
- 到达活动开始时间即不再属于“活动开始前”，报名与取消均不可进行。开始时间及其判定沿用现有产品规则，本次不修改时间规则，也不支持开始时间变更。

**范围边界**

本次仅提供用户本人的报名与取消能力，不做候补、支付、代报名或通知；不新增管理员代用户取消报名的入口。
