**背景与目标**

为线下活动提供用户自主报名和取消能力，减少工作人员手工登记。已登录用户可以在活动开始前为自己报名、取消报名，并在取消后满足条件时重新报名。

**核心业务规则**

“有效报名”指用户报名成功且尚未取消的报名，每份有效报名占用一个名额。

| 场景 | 业务规则与结果 |
|---|---|
| 首次报名或取消后重新报名 | 活动尚未开始、用户已登录、本人没有该活动的有效报名，且活动仍有名额时，可以报名；成功后形成一份有效报名，占用一个名额。 |
| 重复报名 | 同一用户在同一活动中最多有一份有效报名；重复操作不得新增有效报名或额外占用名额。 |
| 名额已满 | 不能报名，不能新增有效报名。 |
| 活动已开始 | 不能报名，也不能重新报名。 |
| 取消报名 | 用户只能在活动开始前取消自己的有效报名；取消成功后，该报名不再有效，立即释放一个名额。 |
| 没有有效报名时取消 | 不能取消，也不能释放名额。 |
| 活动已开始后取消 | 不允许取消，不释放名额。 |
| 报名或取消失败 | 失败操作不得改变原报名情况或剩余名额。 |

活动开始时间及是否已开始的判断沿用现有产品规则，本次不另行定义时间规则，也不支持活动开始时间变更。

**重要边界与验收要点**

- 未登录用户不能报名；用户不能为他人报名或取消他人的报名。
- 多个用户同时争取最后一个名额时，最多只能有一人报名成功，不能超额报名。
- 同一用户连续或同时重复报名，最终最多产生一份有效报名、占用一个名额。
- 对同一份有效报名重复取消，最多释放一次名额；取消成功后再次取消，按“没有有效报名”处理。
- 取消成功后释放的名额可用于后续报名。原用户重新报名时，仍需满足活动未开始且有名额，不保留其原名额。
- 验证失败操作不改变报名和名额时，应排除其他用户成功报名或取消造成的正常变化。

**本次范围外**

候补、支付、代报名、通知，以及活动开始时间变更。管理员目前没有代用户取消的入口，本次不新增该入口。

重复报名的具体反馈方式、页面布局及提示文案可在后续交互设计中确定，不影响上述业务规则。
