**任务分配站内通知需求**

本需求用于已有任务系统：让负责人知道任务已分配给自己，减少遗漏处理。

**通知生成规则**

- 任务成功分配给一名负责人时，为该负责人生成一条站内通知，初始为未读。本人给自己分配任务也通知。
- 分配失败时，不生成通知。
- 重复保存任务且负责人未变时，不新增通知。
- 负责人改为另一人时，只为新负责人新增一条通知，旧通知保留。
- 通知生成失败不回退任务分配结果。向分配操作人说明“任务已分配，但通知未送达”，本次不做自动补发。因此，再次保存且负责人未变时，也不触发补发。

**通知查看与已读规则**

- 每人只能查看和操作自己的通知。
- 通知列表按生成时间从新到旧排列；生成时间相同的通知不要求固定先后顺序。
- 没有通知时，显示“暂无通知”。
- 点击通知后，将该通知标为已读。
- 重复打开通知不生成新通知，也不恢复未读。
- 不支持标回未读或删除通知。

**通知内容与任务访问**

每条通知显示生成时的任务名称和分配人。任务后来改名或删除，通知仍保留生成时的信息。

打开通知时，按任务当前权限判断是否允许访问：

| 任务当前情况 | 打开后的行为 | 通知状态 |
|---|---|---|
| 任务存在，接收人有访问权限 | 允许查看任务详情 | 标为已读 |
| 任务已删除 | 说明无法访问 | 标为已读 |
| 接收人已无访问权限 | 说明无法访问，不展示无权查看的任务详情 | 标为已读 |

通知中的历史信息不代表接收人持续拥有任务访问权限。

**主要验收场景**

| 场景 | 预期结果 |
|---|---|
| 成功给他人或自己分配任务 | 负责人收到一条未读通知 |
| 分配失败 | 不生成通知 |
| 保存任务但负责人未变 | 不新增通知 |
| 负责人由甲改为乙 | 仅为乙新增未读通知，甲的旧通知保留 |
| 用户尝试查看或操作他人的通知 | 不允许 |
| 首次点击、重复打开同一通知 | 通知保持已读，不新增通知 |
| 任务改名后查看旧通知 | 仍显示生成时的任务名称和分配人 |
| 任务删除或接收人失去权限后打开通知 | 提示无法访问，通知标为已读，不展示受限任务详情 |
| 任务分配成功，但通知生成失败 | 分配结果保留，向分配操作人提示通知未送达，不自动补发 |
| 通知列表为空 | 显示“暂无通知” |

**范围与后续设计**

本次不包含邮件、短信、推送、批量操作或通知历史迁移。数据库、消息队列、接口形式和分页实现由后续技术设计确定。

当前核心业务规则已明确，可据此开展技术设计、开发和测试。
