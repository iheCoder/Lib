现有描述已足够明确，可以整理为以下需求，供后续设计、开发和测试使用。

**背景与目标**

为线下活动增加用户自助报名和取消报名的能力，减少工作人员手工登记。已登录用户可以在活动开始前为自己报名，也可以取消自己的有效报名。

**报名与取消规则**

| 场景 | 业务规则与结果 |
| --- | --- |
| 用户报名 | 用户须已登录，只能为自己报名。活动尚未开始且有剩余名额时，可以报名。 |
| 报名成功 | 用户获得该活动的一份有效报名，占用一个名额。 |
| 重复报名 | 每位用户在每场活动中最多有一份有效报名；重复操作不能产生额外有效报名，也不能多占名额。 |
| 名额已满 | 不能新增报名。 |
| 用户取消 | 用户只能在活动开始前取消自己的有效报名。 |
| 取消成功 | 原报名不再有效，立即释放其占用的一个名额。 |
| 没有有效报名时取消 | 不能取消，也不能因此增加剩余名额。 |
| 取消后重新报名 | 活动尚未开始且仍有名额时，可以重新报名；取消不保留名额。 |
| 活动开始后 | 不能再报名，也不能再取消报名。 |
| 报名或取消失败 | 失败操作不得改变原报名或剩余名额。 |

**关键边界与验收场景**

以下场景也必须满足上述规则：

- 同一用户重复提交报名，包括同时提交多次，最多形成一份有效报名，并只占用一个名额。
- 多名用户同时争抢最后一个名额，最多一人报名成功，不能超额报名。
- 同一份报名重复取消，最多释放一次名额；取消成功后再次取消，按“没有有效报名”处理。
- 取消释放的名额可供其他用户报名；原用户重新报名时，需要重新满足报名条件。
- 报名失败不能留下新增的有效报名或扣减名额；取消失败应保留原有效报名及其占用的名额。

活动是否已经开始，沿用现有产品提供的开始时间及时间规则。本次不另行定义时间判定方式，也不支持修改活动开始时间。

**本次范围**

提供用户为自己报名、取消及取消后重新报名的能力。不包含候补、支付、代报名或通知；本次也不新增管理员代用户取消的入口。

页面布局、按钮文案及具体失败提示可在后续交互设计中确定，不影响以上业务规则。
