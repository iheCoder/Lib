# requirement_define 手工验证材料 v1

这是一套可逐条发送的开发评估材料：5 组、12 案例。尚未运行，不能据此认定 skill 有效。只准备材料，不含自动运行程序，不修改被测 skill。

## 最快开始

1. 主持人读本页、reviewer/rubric.md 和所选案例的 reviewer/cNN.md。
2. 为案例开一个全新任务，不复用本次材料设计对话。只把该案例的 input.md 和 materials/（若有）复制到一个独立工作目录，保持相对位置；answer-*.md、turn-*.md 留在主持人手中。只向被测 Agent 提供当前轮输入和公开材料。
3. 技能组加载 requirement_define/SKILL.md；给出统一开场：“请使用 requirement-define skill 帮我梳理下面的需求。”随后粘贴 input.md 原文。基线组只把开场改为“请帮我梳理下面的需求。”且不加载该 skill；其他模型配置、工具、材料、用户应答保持相同。
4. 多轮文件由主持人保管，按下表及 reviewer/cNN.md 规定，在上一轮完整结束后才发送。不要提前复制到被测工作目录。不要额外提示“你漏了……”“现在生成文档”。
5. 保存每轮完整回答、工具记录、最终文档。复制 results-template.md 填写；不要在模板中预填成功。

**隔离边界：**文件分目录不等于隔离权限。被测 Agent 不应看到本 README、reviewer/、其他案例、未发送的后续消息或评分结果。不要让它在本仓库中自行读取整个 eval 目录。最稳妥的是使用只提供当前材料的新任务/受限环境；若宿主仍允许读取本仓库，记录实际读取轨迹。已读评判参考或其他案例答案的运行标记 CONTEXT_CONTAMINATED，单独保留，不能用于独立效果结论。

新任务如果自动载入本次讨论记忆或完整历史，也不算干净上下文。基线若自动触发同一 skill，标记条件污染，不能作为无 skill 对照。

## 工具与附件准备

- c04/c05：只复制 input.md 和 materials/ 中的两个公开文件；先确认两个文件可读。它们没有先后时间或优先级暗示。可用文本附件替代文件工具，但这时只证明材料冲突处理，不证明工具读取能力。
- c11：工作目录中 materials/refund-policy.md 必须不存在，不要创建一个包含“读取失败”字样的假文件。提供真实文件读取工具，保存实际错误。其他案例的工具故障属于环境异常，不自动算 skill 错误。
- 其余案例可纯文本运行。若宿主提问控件异步返回，仍以完整回答/问题实际送达后再发送下一条为准。
- 无需开放网络；所有业务事实来自固定材料。被测 Agent 不能靠搜索其他退款规则补替本案例缺失的正式规则。

## 通用应答与停止规则

- Agent 问的是已提供信息：主持人可原样重贴相关句子一次，并记录重复询问；不改写、增加规则或提示评分重点。第一轮是否完成仍按第一轮记录判断。
- c01/c06：语义问到目标问题即可发对应答案，不要求关键词。若只问无关问题，可答一次：“目前没有其他补充，请依据已有信息继续梳理。”仍未触及关键未知则结束，记录未完成，不无限陪聊。
- 其他固定轮次案例：按预设顺序发送，不因它的回答更好或更差而临时增加提示；错误检查点不得被后续成功覆盖。
- 未准备但被指出的真实重要歧义：不要临场决定答案，也不要自动判 Agent 多问。记录 UNKNOWN/疑似材料缺陷，由主持人复核；确有歧义则判 FIXTURE_ISSUE，修订版本后重跑两组。
- 技术/环境中断、用户未送达消息等记 INCONCLUSIVE 或 ENVIRONMENT_GAP，不伪装成业务失败。
- 不设一个总提问数阈值判输赢；重点看是否存在值得确认的问题、是否重复阻塞。若额外采用时间/token 上限，运行前固定并记录；因上限停止单列。

## 推荐运行规模

先跑 c01/c02/c03/c08/c09/c10 六例，确认材料和评分可用，再跑全套。开发初筛可每例每条件独立重复 3 次：全套两条件共 72 次。三次只用于发现明显错误，不作为可靠性保证。

若只想检查当前 skill，可先只跑技能组。要说“skill 带来提升”，必须有同模型、同配置、同材料的无 skill 对照，交替或随机运行两条件，逐案例比较，不把不同条件混在一个上下文里。

记录模型版本、推理/采样设置（无法设置则记宿主默认/未知）、宿主 system/developer 约束、工具能力、skill 内容哈希、日期及停止原因。独立记录关键错误次数、每例成功次数/有效次数、未完成和环境问题；不以总平均分掩盖权限编造等错误。小样本报原始计数，不声称“永不失败”。

## 结论边界

这些场景来自本次已经讨论过的设计，是开发案例，不是保留测试集。材料作者未做独立盲评。评分者不应知道技能组/基线组身份；先用 rubric.md 中正反例校准，再评分输出。有争议保留证据和 UNKNOWN，不强行打分。

本版本没有加入信息顺序变体或新的隐藏业务，避免扩大已确认的 12 例范围。后续若针对这些例子调优，必须另补未见过的场景或真实需求回放验证泛化。

## 文件说明

- cases/：按案例分开的原始输入、公开业务材料、主持人按时发送的后续消息。
- reviewer/：逐例判据、回答触发条件和最终文档理解检查；不要交给被测 Agent。
- results-template.md：一次尝试的记录模板。
- manifest.json：材料清单、SHA-256 校验和、被测 skill 快照哈希；仅用于追溯版本，不是测试成绩。
