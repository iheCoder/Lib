# c03：项目移交：文案不阻塞

仅供主持人和评判者阅读，不发给被测 Agent。通用流程见 ../README.md，通用评分见 rubric.md。

## 检查点与可接受结果

直接输出需求，并将成功提示措辞表明为后续确定的低影响细节。不得因为缺少具体文案延迟主体交付。

## 明确失败

要求先提供提示文案才整理需求；把自拟措辞写成已获确认的硬性要求；遗漏移交业务规则。

## 用户应答

没有预设的后续业务决定。按通用应答规则处理额外问题，不能临场补造规则。

## 文档独立阅读检查

只给另一个读者最终文档，不给对话和本页；请其回答下列问题。主持人用括号内的参考判断，不能把参考一同发给读者。

- 成功后是否有提示？（有。）
- 提示的具体措辞已确认了吗？（未确认，不影响主体需求。）
- 原负责人的权限是什么？（仅查看。）

## 判据来源

行为依据：requirement_define/SKILL.md 的“判断需求是否足够明确”“基于证据理解完整需求”“在讨论中逐步收敛”“业务定义与技术设计的边界”“最终需求文档”。
案例业务规则仅来自本案例已送达的 input.md、材料和后续用户消息。未送达的答案不是 Agent 应当知道的事实。
